31"""The Python Garbage Collector (`GC`_) doesn't usually get too much 

32attention, probably because: 

33 

34 - Python's `reference counting`_ effectively handles the vast majority of 

35 unused objects 

36 - People are slowly learning to avoid implementing `object.__del__()`_ 

37 - The collection itself strikes a good balance between simplicity and 

38 power (`tunable generation sizes`_) 

39 - The collector itself is fast and rarely the cause of long pauses 

40 associated with GC in other runtimes 

41 

42Even so, for many applications, the time will come when the developer 

43will need to track down: 

44 

45 - Circular references 

46 - Misbehaving objects (locks, ``__del__()``) 

47 - Memory leaks 

48 - Or just ways to shave off a couple percent of execution time 

49 

50Thanks to the :mod:`gc` module, the GC is a well-instrumented entry 

51point for exactly these tasks, and ``gcutils`` aims to facilitate it 

52further. 

53 

54.. _GC: https://docs.python.org/2/glossary.html#term-garbage-collection 

55.. _reference counting: https://docs.python.org/2/glossary.html#term-reference-count 

56.. _object.__del__(): https://docs.python.org/2/glossary.html#term-reference-count 

57.. _tunable generation sizes: https://docs.python.org/2/library/gc.html#gc.set_threshold 

58"""

68def get_all(type_obj, include_subtypes=True): 

69 """Get a list containing all instances of a given type. This will 

70 work for the vast majority of types out there. 

71 

72 >>> class Ratking(object): pass 

73 >>> wiki, hak, sport = Ratking(), Ratking(), Ratking() 

74 >>> len(get_all(Ratking)) 

75 3 

76 

77 However, there are some exceptions. For example, ``get_all(bool)`` 

78 returns an empty list because ``True`` and ``False`` are 

79 themselves built-in and not tracked. 

80 

81 >>> get_all(bool) 

82 [] 

83 

84 Still, it's not hard to see how this functionality can be used to 

85 find all instances of a leaking type and track them down further 

86 using :func:`gc.get_referrers` and :func:`gc.get_referents`. 

87 

88 ``get_all()`` is optimized such that getting instances of 

89 user-created types is quite fast. Setting *include_subtypes* to 

90 ``False`` will further increase performance in cases where 

91 instances of subtypes aren't required. 

92 

93 .. note:: 

94 

95 There are no guarantees about the state of objects returned by 

96 ``get_all()``, especially in concurrent environments. For 

97 instance, it is possible for an object to be in the middle of 

98 executing its ``__init__()`` and be only partially constructed. 

99 """

125class GCToggler: 

126 """The ``GCToggler`` is a context-manager that allows one to safely 

127 take more control of your garbage collection schedule. Anecdotal 

128 experience says certain object-creation-heavy tasks see speedups 

129 of around 10% by simply doing one explicit collection at the very 

130 end, especially if most of the objects will stay resident. 

131 

132 Two GCTogglers are already present in the ``gcutils`` module: 

133 

134 - :data:`toggle_gc` simply turns off GC at context entrance, and 

135 re-enables at exit 

136 - :data:`toggle_gc_postcollect` does the same, but triggers an 

137 explicit collection after re-enabling. 

138 

139 >>> with toggle_gc: 

140 ... x = [object() for i in range(1000)] 

141 

142 Between those two instances, the ``GCToggler`` type probably won't 

143 be used much directly, but is documented for inheritance purposes. 

144 """
